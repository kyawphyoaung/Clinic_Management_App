# Medical Tourism Management Web App - Feature Specification

## 1. Request Deposit Form (Revised)
**Location**: In the patient management section (e.g., partner dashboard or admin area).  
**Purpose**: Allow partners or staff to request a deposit from a patient, using **only TWD** as currency (no exchange rate logic).  

**UI Components**:
- **Patient Name**: Text field (pre-filled or searchable).
- **Country**: Text field or dropdown (display only).
- **Amount (TWD)**: Numeric input field. The UI must clearly label it as **"Amount (TWD)"** and indicate that all amounts are in New Taiwan Dollars.
- Example layout:
  ```
  Patient: Kyaw Kyaw
  Country : United States of America
  Amount (TWD): [     5000     ]
  ```
- No currency conversion or multi-currency support in this form.

## 2. Partner Dashboard

### 2.1 Remove Unused Card
- Remove the **"Patient's Requested Deposit Amount"** card from the dashboard.

### 2.2 My Referred Patients Table
- Replace the existing table with the following columns (in order):
  - **Patient ID**
  - **Full Name**
  - **Status** (e.g., Active, Inactive, etc.)
  - **Registered At** (timestamp)
  - **Deposit Amount** (numeric, displayed with TWD if needed)
  - **Completed Treatments** (count)
  - **Commission Amount** (numeric, with TWD)

  - If the deposit status is **"awaiting"** (or pending), the text/background should be **red**.
  - If the deposit status is **"received"**, it should be **green**.
  - (The status is determined by the deposit record; colour coding helps visual identification.)

### 2.3 KPI Cards – Total Commission Amount (August 2026)
- The KPI card titled **"Total Commission Amount (August 2026)"** displays the sum of commissions for that month.
- **Colour rule**:
  - If the commission record status is **"paid"**, the amount should be shown in **green**.
  - If the status is **"pending review"** or **"pending payment"**, the amount should be shown in **orange**.
- This card should be prominently placed among other KPIs.

## 3. Add Notes (SOAP Notes with Body Diagram)

### 3.1 Navigation
- Clicking the **"Add Notes"** button (or similar) shall navigate to a **new page** (not a popup/modal). The user must be taken to a dedicated page for entering notes.

### 3.2 Page Layout and Content

#### Top Section
- **Last updated** timestamp (e.g., "Last updated April 20, 2026 8:51 PM (TWD)").
- **Doctor Name** (e.g., "Doctor Aung Myat Thu").
- **Save / Update** button (toggles based on new vs existing record).

#### Patient Information (Left/Top)
- **Profile Avatar** (placeholder or actual image).
- **Patient Name**
- **Date of Birth**
- **Age** (calculated)
- **Country**

#### Diagram Tabs
- Tabs: **Full Body**, **Urology**, **Brain**.
- Default: Full Body.
- For **Full Body**, there should be two images: front and back (separate or switchable). All images are in **WebP** format and should be displayed at a large, clear size.

#### Body Diagram with Pins
- The diagram is a **static image** (no interactive drawing) but allows **overlay pins**.
- Pins can be placed by clicking on the image; each pin is stored with **coordinates (x, y)** relative to the image.
- Pins are displayed as markers (e.g., "Pin A1", "Pin A2").
- Below the diagram, list each pin with its **description** (text field). For example:
  - Pin A1: "Patient reports pain …"
  - Pin A2: "Swelling noted here …"
- The system must store the pin coordinates and descriptions so that when revisiting the note, the pins reappear exactly at the correct positions on the image.

#### Vital Signs
- Blood Pressure Systolic (mm Hg)
- Blood Pressure Diastolic (mm Hg)
- Heart Rate (bpm)
- Body Temp (°C)
- Weight (kg)
- Height (cm)

#### SOAP Sections (Long Text Boxes)
- **Subjective**
- **Objective**
- **Assessment**
- **Plan**

#### Action Buttons
- **Save** (or Update)
- **Delete** (if existing)
- **Cancel** (return without saving)

## 4. Record Management – View, Update, Delete

### 4.1 General Record Actions
- For each record (e.g., patients, invoices, payments), provide **View**, **Update**, and **Delete** buttons.
- **View** button: opens a **popup/modal** that displays all editable data. The popup acts as an edit form where the user can modify fields.
- **Update** button: appears inside the popup; clicking it saves changes and closes the popup.
- **Delete** button: performs deletion (with confirmation).

### 4.2 Payment Record Updates (Charges / Invoices)
- When editing a payment record, the user must be able to **link** or **unlink** charges (now called invoices) to that payment.
- In the edit popup, show the list of associated invoices and allow toggling selection.
- **Add Charge / Add Invoice** function:
  - When adding a new line item, the user selects a **Service Category** from a dropdown.
  - If the category **"OTHER"** is selected, a **text box** appears immediately below to allow the user to type a custom name (instead of using a fixed "OTHER" label).
  - **Price** field: do **not** validate on each keystroke (i.e., allow empty temporarily). Validation should only occur when the user clicks **"Add Line"** (or equivalent) – if the price field is empty, show an alert and prevent adding.
  - This improves UX, as the user can fill in other fields first.

### 4.3 Invoice UI Redesign
- All occurrences of "Charge" should be renamed to **"Invoice"**.
- Each invoice gets a unique ID in the format: **#000001**, **#000002**, ... up to **#999999**. After that, the next ID should be **#1000000**, then **#1000001**, and so on (i.e., increment as a number without leading zeros after 999999).

#### Add Invoice – New Page
- Clicking **"Add Invoice"** navigates to a **new dedicated page** (not a popup).
- This page has an **A4-size paper-like background** with a white/paper texture.
- **Header**:
  - Left: Logo – use `public/images/main_logo.svg` (Revivora Medical Tourism).
  - Right: **"INVOICE"** heading, and below it the **Invoice #ID** (e.g., #000123).
- **Bill To** section (left):
  - Patient Name
  - Address
  - Country
  - Phone Number (displayed decrypted – the system should decrypt before showing)
- **Date** (right side, display current date or editable).
- **Invoice Table** (below Bill To):
  - Columns: **Description**, **Price**, **Qty**, **Total**.
  - Table style:
    - Outer border (full border around the table).
    - A floating border line under the table header row (not a full grid; only horizontal line after header).
    - Rows are separated by spacing (vertical gaps) rather than cell borders.
    - The subtotal, discount, and total are displayed at the bottom (right-aligned).
  - Example layout:
    ```
    _________________________________________________________
    Description            Price        Qty        Total
    _________________________________________________________
    Medication             NT$300       1          NT$300
    LAB                    NT$5000      1          NT$5000
                                 Subtotal          NT$5300
                                 Discount          0% (NT$0)
                                 Total             NT$5300
    _________________________________________________________
    ```
- **Save & Print Invoice** button:
  - Clicking saves the invoice data into the system.
  - Immediately after saving, trigger a **PDF generation and print dialog** (A4 size) so the user can print or save as PDF.
- The page should be clean, with the invoice centered, resembling a real invoice document.

## 5. Cashflow Page

### 5.1 Key Performance Indicators (KPI Cards)
- **Total Revenue** – sum of all income (including deposits, invoice payments, etc.).
- **Total Agent Commission Amounts** – total commissions paid or accrued to partners.
- **Net Profit** = Total Revenue – Total Expenses (including hospital costs, travel, agent commissions, etc.). This should be calculated automatically.

### 5.2 Inflow & Outflow Visualization
- **Chart type**: Combination of **bar chart** (for monthly totals) and **line chart** (for cumulative trend) – or use a dual-axis chart.
- Show **Inflow** (all incoming cash) and **Outflow** (all outgoing cash) over time (monthly).
- Include a **Cash Flow Forecast** – a projection for the next 3–6 months based on historical data and pending invoices/deposits. This can be a separate chart (line chart with dashed lines for forecast).

### 5.3 Financial Analysis – Revenue by Source
- Breakdown revenue by:
  - **Patient Groups** (e.g., individual, corporate, etc.)
  - **Treatment Types** (e.g., surgery, consultation, therapy, etc.)
  - **Country of Origin** (where the patient comes from).
- Use **pie charts** or **stacked bar charts** to visualize these distributions.

### 5.4 Detailed Financial Tables
- **Payment Status of Each Patient**: a table listing patients with columns:
  - Patient Name
  - Total Deposits
  - Total Invoice Payments (paid)
  - Outstanding Balance (if any)
  - Overall Status (e.g., Paid, Partial, Overdue)
- Include a filter by date range and status.

### 5.5 Multi-Currency Support (Flow Analysis)
- Even though the system operates primarily in TWD, track the **original currency** of incoming funds (e.g., USD, EUR, JPY).
- Show a **bar chart** or **table** indicating:
  - For each country, the total amount received in its local currency and the equivalent in TWD (using the exchange rate at the time of transaction).
  - This helps understand the currency composition of cash inflow.
- Display a **Currency Distribution** pie chart showing the proportion of TWD vs. other currencies (based on original amounts converted to TWD).

### 5.6 Additional Cashflow Metrics (to be displayed as cards or small charts)
- **Days Payable Outstanding (DPO)** – average days to pay suppliers.
- **Days Sales Outstanding (DSO)** – average days to collect from patients/insurers.
- **Operating Cash Flow** – net cash from operations.
- These can be calculated from the payment and invoice data.

### 5.7 Recommended Chart Libraries
- Use well-known libraries like **Chart.js**, **Recharts**, or **D3.js** to implement the visualizations. The charts should be interactive (hover for details, click to filter).

### 5.8 UI/UX Notes
- All charts should be responsive and clearly labeled.
- Provide date-range pickers to filter data across the page.
- Use a consistent colour scheme: green for positive (inflow/profit), red for negative (outflow/loss), and orange for pending/warning.
